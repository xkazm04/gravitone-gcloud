# The style contract

The Phase 1 exit test (`docs/next/migration-plan.md` §6, §9.6.1): the approved prototype's own pages
are measured role by role, and `/kit` must draw every role the same way.

## Run it

```bash
node pipeline/style-contract.mts                 # capture every page, then check /kit; exit 0/1/2
node pipeline/style-contract.mts --check-only    # check against the committed contract.*.json
node pipeline/style-contract.mts --page floor    # one page (repeatable)
node pipeline/style-contract.mts --app http://localhost:3184   # use an app you already started
```

The Director registers it as `"style-contract": "node pipeline/style-contract.mts"`.

What the script does, in order:

1. If `docs/next/prototype/data/` is missing (it is git-ignored), it runs
   `node docs/next/prototype/tools/rebuild-data.mts`.
2. It serves `docs/next/prototype/` as plain static files on `127.0.0.1:3194`. The root is the
   prototype folder, not `app/`, because the pages load `../data/`.
3. Unless `--app` is given, it starts `next dev -p 3184` with `NEXT_PUBLIC_DEV_AUTH=1` and
   `NEXT_DIST_DIR=.next-style-contract`. On exit it stops the server, removes that directory and
   restores `tsconfig.json`, which `next dev` edits.
4. For every `roles.<page>.json` it runs `capture` against the prototype page, then `check`
   against `/kit`.

Override with `STYLE_CONTRACT_TOOL` (path to `style-contract.py`, default
`../ai-registry/skills/contest/scripts/style-contract.py`), `PYTHON`,
`STYLE_CONTRACT_PROTO_PORT` and `STYLE_CONTRACT_APP_PORT`. Python needs `playwright` with
Chromium installed. Width is 1440x900.

## Files

| File | What it holds |
| --- | --- |
| `roles.<page>.json` | `page`: the winner path under `docs/next/prototype/`, the port path, and the clicks each side needs before measuring (`drive` on the prototype, `portDrive` on the app). `roles`: one `winner` selector (prototype) and one `port` selector (`/kit`) per role. The Python tool reads only `roles`. |
| `contract.<page>.json` | What `capture` measured on the prototype. Regenerated by every run that is not `--check-only`. |

Pages: `floor` (`index.html`), `board` (`#board`, matrix cull), `pair` (`#open=pkt_dojo`, blind
pair), `review` (`#open=pkt_prj_glass_harbor_trailer_cut`, packet review), `plan`
(`projects.html#plan`), `runs` (`#runs`), `library`, `ledger`. The Ledger's toast exists only after
its copy button is pressed; the kit's `copy` button raises the same toast.

Every page also measures the header roles: `ground`, `header`, `brand`, `nav-rest`, `nav-current`,
`chip`, `chip-value`, `tally`, `keycap`. A role that appears on several pages has one port
specimen, in the `/kit#contract` section (`app/(studio)/kit/Contract.tsx`). Where a role's text
differs from page to page, the specimen draws that page's text under a `role@page` hook. The
instrument measures width, so a specimen with different text would fail on the text rather than
on the design.

Width measures nothing for the column-bound roles (`panel`, `field`, the facet rows, section
headings, `error`, `stackbar`, `button-cyan` on Plan). The kit draws them in a frame set to their
page's column width, as kit.js did, so there width matches by construction. The phase that builds
each page holds that width against the real route.

## Reading a result

The runner prints the tool's own table, and then one adjustment of its own. Chrome serialises a
`color-mix()` colour as `color(srgb …)` and a literal colour as `rgba(…)`, and the tool compares
the two as strings. A row counts as "notation-only" only when both sides parse as sRGB and match
on every 8-bit channel to within 1. Those rows are still printed. They exist because `@gt/ui`
derives tone borders from their hue (`ADMISSION.md` rejects per-hue literal roles). The proper fix
is in the tool's `differs()`. As a guard, the runner refuses (exit 2) when its own count of the
table's rows differs from the tool's count.

## Accepted deviations (owner ruling, 2026-10-15)

The prototype disagrees with itself on three points. The owner ruled that the shared sheet
(`tokens.css`) wins over a page's local redefinition, and that the search field reserves 34px.
Each row is recorded as `accept` on its role, so a run reports it as accepted rather than failing.
`accept` is for owner rulings only.

| Page · role | Property | Prototype (winner) | Kit | Why it is open |
| --- | --- | --- | --- | --- |
| board · `button`, review · `button-emerald`, `button-rose` | paddingRight | 8px | 10px | `floor.css` redefines `.btn` with `padding:0 8px 0 12px`. `tokens.css`, which Plan, Runs, Library and Ledger use, has `0 10px 0 12px`. |
| floor · `toggle-off` | color | `--faint` | `--muted` | `floor.css` redefines `.toggle` at rest as `--faint`. `tokens.css` uses `--muted`. |
| library · `field` | paddingRight | 32px | 34px | Both pages reserve room for the search keycap: Library 32px, Ledger 34px. `tokens.css` reserves nothing, so typed text ran under the cap. The kit takes 34px (inset + cap + inset, mirroring the glyph side), so Ledger holds and Library is listed. |

Known questions this contract does not measure: the brand's 20px vs 19px (inside the 1px
tolerance, so it passes; still the owner's call), the kit index's 220px width, the section max
width and the Ghost row heights (Lot 7).

The kit cannot draw these prototype features yet. They are left out of the roles, not hidden:

- a `Seg` option with a glyph (Ledger actors)
- a `Toggle` with a keycap or a glyph (Library "detail ]", Ledger "newest")
- a `SourceTag` with a count (Library corpus legend "254 real")
- a `Tally` inside a `Button` (Ledger "history 9"; `Button` takes a `Chip` badge)
- a glyph after a button's label (Ledger "Open record ›")
- an act in a `Panel` head (Plan "+ Compose")

Not drawn on any named page in a reachable default state, so not measured: the amber and violet
`Button`, the `paused` status. The running pip is left out because its pulse animates
`box-shadow`, so the reading depends on the frame.
